# HTTP/4 (`http4` v0.2.0) — Русская документация

> **[🇬🇧 English README](README.md)** · **[Руководство по интеграции](docs/INTEGRATION.md)** · **[Спецификация протокола](spec/http4.md)** · **[Модель безопасности (EN)](SECURITY.md)**

[![CI & Sanitizers](https://github.com/wisoqu/http-4/actions/workflows/ci.yml/badge.svg)](https://github.com/wisoqu/http-4/actions/workflows/ci.yml)

> **Статус — экспериментальный черновик и исследовательский прототип:** `http4` — независимый инженерный прототип агент-ориентированной семантики поверх HTTP. Проект **не** является стандартом IETF, не связан с рабочей группой IETF HTTP WG и пока не проходил независимый внешний криптоаудит или формальную верификацию (Tamarin/ProVerif).

**Экспериментальный агент-ориентированный, экономически осознанный семантический слой для HTTP** — с опциональным **нативным C11 Node-API ускорителем** (и автоматическим чистым JS-фоллбэком), **нулевыми runtime-зависимостями**, **полными TypeScript-типами** и **интеграцией за 1 команду или 1 строчку кода** в существующие проекты (Python/FastAPI, Go, Express, Next.js, Cloudflare Workers, Bun).

**Транспортная архитектура:** семантика `http4` отделена от транспорта. Кодирование целых чисел использует RFC 9000 §16 QUIC-varint (плюс профиль расширения HTTP/3 RFC 9114 §7.2.8 в `src/h3-compat.js`), чтобы кадры ложились в QUIC-потоки без переупаковки. В текущей Node.js-реализации референсный бинарный транспорт (`src/wire.js`) работает поверх мультиплексированного **TLS 1.3 / TCP** (`ALPN: h4`) наряду с HTTP/1.1 и HTTP/2 гейтвеями (`src/gateway.js`); нативный UDP/QUIC-носитель — планируемый будущий биндинг.

## Зачем нужен `http4` (какие проблемы он решает)

Классический HTTP проектировался под человека в браузере. В агентских и LLM-нагрузках ломаются три допущения:
1. **Штормы ретраев сжигают вычисления на GPU/API:** 50 агентов одновременно повторяют один тяжёлый запрос — бэкенд запускает 50 одинаковых вызовов модели вместо одного. `http4` схлопывает идентичные in-flight запросы (**singleflight coalescing**: 50 запросов → **1 вычисление**).
2. **Суб-агенты упираются в централизованную авторизацию:** оркестратор порождает узких подагентов; раздавать мастер-ключ опасно, а ходить на OAuth-сервер на каждый хоп накладно. В `http4` агент офлайн дописывает сужающее звено `HMAC-SHA256-128` (`~2.0 µs` чистый C11 HMAC; `~5.8 µs` полный разбор и пересборка токена), ограничивая `scope`, `caps`, `tenant` и `expiresAt` — любое расширение прав отклоняется при верификации в рамках стандартной стойкости HMAC-SHA256.
3. **Rate-limit по IP режет честных агентов за общим CGNAT/облаком:** в симуляции `npm run attack` (`40,000` запросов за 8 общими IP, ~69 агентов на IP) классический per-IP лимитер пропускает лишь **6.0%** честных запросов (блокируя **94.0%**). `http4` обслуживает **50.0%** всех попыток честных агентов (**100% их выделенной квоты 50/окно**, а оставшиеся **50.0%** сверх квоты клиент сам останавливает локально до выхода в сеть) и снижает долю атакующих с **6.0% до 1.1%**, назначая `34,600` крипто-задач Proof-of-Effort.
   - *Важное уточнение про `h4-pass` (`http4/overload-pass`, алиас `http4/privacy-pass`):* несмотря на историческое имя файла `privacy-pass.js`, токен `h4-pass` — это **одноразовый `HMAC-SHA256-192` пропуск перегрузки, связываемый издателем (issuer-linkable)**, а **не** слепые подписи IETF Privacy Pass (RFC 9576–9578 / VOPRF). Он экономит батарею/CPU клиента при перегрузке (`~5.8 µs` полная проверка с защитой от повтора), но не даёт криптографической несвязываемости между выдачей и погашением.

## Установка и 4 способа интеграции

Требуется **Node.js ≥ 20** (0 внешних npm-зависимостей):

```bash
npm install github:wisoqu/http-4
```

- **`postinstall` и чистый JS-фоллбэк:** при установке `scripts/build-native.js` пробует скомпилировать C11-аддон (`cc`/`gcc`/`clang`). Если компилятора в системе нет, установка **завершается успешно** (одной строкой уведомления без стектрейса), а библиотека прозрачно работает на побитово совместимом чистом JS.
- **Отключение сборки аддона:** `H4_SKIP_NATIVE=1 npm install` пропускает компиляцию на этапе установки, а `H4_PURE_JS=1` принудительно включает JS-реализацию в рантайме.

### Способ 1. Без единой строчки кода (Python FastAPI, vLLM, Ollama, Go, Rust)
Поставьте `http4` как легковесный sidecar-прокси перед вашим сервером:

```bash
npx http4 proxy --upstream http://127.0.0.1:8000 --port 8080 --budget 200 --ttl-ms 5000
```

### Способ 2. 1 строчка для Express / Fastify / Node.js
Не читает и не ломает поток тела запроса (`express.json()`, `multer`, GraphQL работают штатно):

```js
import express from 'express';
import { h4Shield } from 'http4/adapters';

const app = express();
app.use(h4Shield({ budget: 200, windowMs: 10_000 }));
app.use(express.json());
app.post('/v1/chat', (req, res) => res.json({ caller: req.h4.subject, ok: true }));
app.listen(3000);
```

### Способ 3. 1 строчка для Next.js App Router / Cloudflare Workers / Bun / Hono

```js
import { withH4 } from 'http4/adapters';

export default {
  fetch: withH4(async (req) => Response.json({ ok: true }), {
    budget: 200,
    defaultTtlMs: 5_000,
  }),
};
```

### Способ 4. Клиентский SDK для мультиагентных систем (`fetch` + стриминг + `F.CANCEL`)

```js
import { createH4Fetch, AgentSession, CAPS } from 'http4';

const h4Fetch = createH4Fetch({ maxEffortBits: 20 });
const orchestrator = new AgentSession({ token: rootGrant, h4Fetch, budget: 100 });

// Офлайн-делегация узкому суб-агенту (~5.8 µs полная пересборка токена, 0 походов в auth-сервис):
const reader = orchestrator.delegate({ caps: CAPS.READ, scope: '/v1/docs', budget: 20 });
const res = await reader.fetch('https://api.example.com/v1/docs/spec');

// Стриминг с отменой генерации на сервере (`F.CANCEL`, ~97 µs на loopback TLS 1.3 + 0.5 RTT в сети):
const ac = new AbortController();
for await (const chunk of orchestrator.stream('h4://api.example.com:8443/v1/llm/stream', { signal: ac.signal })) {
  if (enough) ac.abort();
}
```

Подробный разбор архитектуры — в **[docs/INTEGRATION.md](docs/INTEGRATION.md)**.

## Воспроизводимые замеры

Стенд: **2 vCPU Intel Xeon @ 2.60 GHz, 4 GB RAM, Linux x64, Node.js v22.22.3, GCC 12.2.0** (`C11 N-API`). Повторить на своём железе: `npm run bench` и `npm run attack`.

### 1. Микро- и серверные бенчмарки (`npm run bench`)

| Метрика | Результат (`C11 N-API`) | Примечание / сравнение |
|---|---|---|
| Размер запроса на проводе (4 кейса против HTTP/1.1) | **12 B** (`simple GET`, в `6.0×` меньше `72 B`) · **48–55 B** (`3.0–4.2×`) | У HTTP/2–3 с HPACK/QPACK холодный запрос обычно **30–60 B**, но требует dynamic table состояния на соединение; в H4 динамической таблицы нет (версия статической согласуется в `HELLO.tableVersion`) |
| Разбор полного бинарного запроса (`79 B`) | **~693 ns** (`1.44 M ops/s`) | `~717 ns` на чистом JS |
| Чистый примитив `HMAC-SHA256-128` | **~1.95 µs** (`0.51 M ops/s`) | `~2.75 µs` на чистом JS |
| Полный `attenuate()` (1 хоп) / полный `PassIssuer.redeem()` | **~5.79 µs** / **~5.77 µs** | Включая разбор/сборку токена или base64url + таблицу повторов (`~7.5 µs` / `~7.2 µs` чистый JS) |
| Верификация `verify()` (2 хопа, кэш корня vs холодный Ed25519) | **~13.7 µs** против **~144.8 µs** | Кэш корневой подписи ускоряет проверку в **11×** |
| Полный цикл `H4Server` (sync) vs отказ (`REJECT`) | **~20.6 µs** (`~48.7k req/s`) vs **~8.6 µs** | Отказ в **2.4×** дешевле обслуживания |
| Остановка стрима `F.CANCEL` (loopback TLS 1.3) | **~97 µs** медиана (`< 0.15 ms`) | От `ac.abort()` клиента до `AbortSignal` роута (`+ 0.5 RTT` в реальной сети) |
| Решение PoE на 1 ядре (`SHA-256`) | **~2.55–2.97 M hashes/s** | Против **~0.52 M hashes/s** на чистом JS (**~5–6×** быстрее) |
| Проверка PoE защитником (`SHA-256` / `4 KiB MemHard`) | **~448 ns** / **~3.32 µs** | Константа O(1) при любой сложности |

### 2. Симуляция L7-флуда за общим CGNAT (`npm run attack`)

Параметры по умолчанию (`bench/attack-sim.js`): **`40,000` запросов** (`5,000` от **50 честных агентов** по 100 попыток; `35,000` от **500 атакующих агентов**) за **8 общими IP** (**~69 агентов на IP**), квота агента `50` ед./10с, классический лимит `300` запр./IP/10с:

| Показатель | Classical (per-IP) | Classical (per-API-key + anon IP) | HTTP/4 |
|---|---:|---:|---:|
| **Честных обслужено** (из `5,000`) | `300` (**6.0%**) | `2,500` (**50.0%**) | `2,500` (**50.0%**) |
| **Честных не обслужено (сверх квоты)** | `4,700` (**94.0%**) | `2,500` (**50.0%**) | `2,500` (**50.0%**) |
| ↳ *из них остановлено на клиенте (не вышли в сеть)* | `0` | `0` | **`2,500`** |
| **Атакующих обслужено** (из `35,000`) | `2,100` (**6.0%**) | `400` (**1.1%**) | `400` (**1.1%**) |
| **Атакующих отбито ценой PoE** | `0` | `0` | **`34,600`** |
| **Процессорное время origin в симуляции** | `~6 ms` *(голый счётчик)* | `~5 ms` *(голый счётчик)* | `~534 ms` *(~14.2 µs/запр.)* |

**Как честно интерпретировать таблицу:**
1. **Почему `50.0%` у честных (`2,500 / 5,000`):** каждый из 50 честных агентов пытается отправить 100 запросов при бюджете 50 на окно. Все 50 агентов получают **100% своей выделенной квоты** (`50 × 50 = 2,500`), а лишние `2,500` запросов в `http4` отсекаются локально на клиенте (`shouldSend()`), вообще не нагружая сеть и сервер (`0` ложных серверных блокировок).
2. **Идентификация против протокола:** классический лимитер по API-ключам тоже даёт `50.0%` / `1.1%`, *если* каждому суб-агенту заранее выдан отдельный ключ в БД. Вклад `http4` — офлайн-выпуск этих 50 токенов из 1 корневого гранта (0 запросов к БД ключей), клиентская самоблокировка до сети и `34,600` платных PoE-вызовов вместо бесплатных `429`.
3. **Время CPU:** классические колонки меряют голый `Map`-счётчик в памяти без парсинга и криптографии, а колонка `http4` выполняет полный цикл разбора кадров, заголовков, проверки макарунов и квитанций (`~14.2 µs` на сетевой запрос).
