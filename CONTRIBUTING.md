# Как участвовать

Правило одно: **каждое утверждение в спеке должно быть либо доказано тестом,
либо измерено бенчмарком.**

## Что считается хорошим патчем

- Новый инвариант в `test/run.js` с номером раздела спеки в названии.
  Приложите вывод, где тест **падает** на старом коде (см. §11 спеки: зелёный
  тест, который никогда не запускался, — это баг, а не покрытие).
- Измерение, заменяющее оценку в `bench/`. Приложите машину и версию Node.
- Правка дизайна с разделом «что это ломает» в описании PR.

## Что не принимается

- Оптимизации без числа до/после.
- Изменения на горячем пути без замера стоимости в `µs/запрос`.
- Новые фичи протокола без раздела «чего это стоит серверу».

## Перед PR

```bash
node test/run.js && node bench/bench.js quick && node demo.js
```
